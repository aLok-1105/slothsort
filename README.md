# SlothSort MVP

A local-first AI organizer for top-level files in a designated folder. React, Node.js, Docker and Ollama.

## Start (Windows PowerShell)

1. Install and start Docker Desktop.
2. From this directory run `docker compose up --build -d`.
3. Run `docker compose exec ollama ollama pull gemma3:270m` (one-time model download).
4. Visit http://localhost:5173 in a recent version of Chrome or Edge.
5. Click **Choose folder & scan**, select a folder, then review suggestions and select which moves to apply.

The browser asks for permission to read and modify the selected folder. SlothSort scans only its top-level files and moves approved files into category subfolders. Test on copies first. Do not expose the service on a public network; it has no authentication.

When running the frontend and backend directly instead of with Docker Compose, the frontend proxy defaults to `http://localhost:3001`. Set `BACKEND_URL` if your backend runs elsewhere. Docker Compose sets it to the internal `backend` service address automatically.

## Notes

- Scans up to 100 top-level files, max 10 MB each, sequentially. Files are uploaded to the local backend only for classification; approved moves happen in the selected folder in your browser.
- Extracts text from TXT, MD, CSV, JSON, LOG and text-based PDFs. Images are classified by extension only; OCR is not implemented.
- Each file is classified by the configured local Ollama model (gemma3:270m). The model uses the filename, extension, and extracted content to propose a descriptive name, a context-specific category, tags, a rationale, and estimated confidence. Categories are generated by the model rather than selected from a fixed list. The prompt treats file content as untrusted input; always review output.
- AI predictions are not guaranteed accurate. Duplicate destination names get numeric suffixes.
- No automatic changes: files move only after user approval.
- No undo/history yet; for MVP test using copies or backups. Future improvement: persistent SQLite undo log.
- Filenames and extracted text are sent to the local backend for classification; the initial model pull needs internet.
